# AGENTS.md

Guidance for AI coding agents working in this repository.

## Overview

`@lobehub/tts` is a TypeScript TTS / STT library for server and browser, with React Hooks and audio components. The package is ESM only and built with `tsdown`. The docs site (<https://tts.lobehub.com>) is built with `@lobehub/docs-kit` (`lobedocs`).

| Path                  | What lives there                                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/core/`           | Framework-agnostic engines (`EdgeSpeechTTS`, `MicrosoftSpeechTTS`, `OpenAITTS`, `OpenaiSTT` in `OpenAISTT/`, `SpeechSynthesisTTS`), shared `data/`, `utils/`, `const/` |
| `src/server/`         | Server helpers that wrap the `openai` SDK                                                                                                                              |
| `src/react/`          | React hooks and components; each `src/react/<Name>/` folder with an `index.mdx` is a docs page                                                                         |
| `src/index.ts`        | `@lobehub/tts` entry (re-exports `src/core`)                                                                                                                           |
| `docs/`               | Docs home (`home/`, entry `home/home.tsx`), `changelog.mdx`, `api-reference/` pages for the core classes                                                               |
| `api/`, `lib/cors.ts` | Vercel Edge functions used as backends by the docs demos (`/api/edge-speech`, `/api/microsoft-speech`, `/api/openai-tts`, `/api/openai-stt`)                           |
| `examples/`           | Standalone server-side usage scripts                                                                                                                                   |
| `docs.config.ts`      | docs-kit config (`atomDirs`, `publicDocs`, nav, aliases)                                                                                                               |

Package entries (`package.json` `exports`, `tsdown.config.ts` `entry`): `@lobehub/tts` → `src/index.ts`, `@lobehub/tts/react` → `src/react/index.ts`, `@lobehub/tts/server` → `src/server/index.ts`. Inside the repo, `@/` and `@lobehub/tts` resolve to `src/`.

## Using Skills

Project skills live in `.agents/skills/<name>/SKILL.md`. Before a matching task, read the whole `SKILL.md` and follow it. If your tool does not load `.agents/skills` automatically, open the file yourself.

| Skill                   | Use it when                                                                                                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `using-docs-kit`        | Writing or changing any docs page: `src/react/*/index.mdx`, demos, `docs/**/*.mdx`, `docs.config.ts`, or fixing a `lobedocs build` error. See also its `reference/config.md` and `reference/validations.md` |
| `building-landing-home` | Changing the docs home page (`docs/home/`, entry `docs/home/home.tsx` set as `homePage` in `docs.config.ts`) with `@lobehub/ui/awesome` components                                                          |

<https://tts.lobehub.com/skills.md> and <https://tts.lobehub.com/llms.txt> are generated by `lobedocs build` from the docs. They are for downstream users of the package, not for working in this repo. Update them by changing the docs, never by hand.

## Writing Docs

- **React hook / component pages**: `src/react/<Name>/index.mdx`, served at `/components/<kebab-name>` (only `src/react` is an `atomDirs` root). Pages are written in English.
- **Core class pages**: `docs/api-reference/<kebab-name>.zh-CN.md` is the source; the English `docs/api-reference/<kebab-name>.mdx` is generated with `bun run i18n-md` (`lobe-i18n`, configured in `.i18nrc.js`; it calls an LLM and needs an API key). If you cannot run it, update both files by hand and keep them in sync. Add new pages to `publicDocs` in `docs.config.ts` and link them from `docs/api-reference/index.mdx`.
- **Changelog**: `CHANGELOG.md` is generated by semantic-release. Do not edit it.

Frontmatter (component pages):

```mdx
---
title: useEdgeSpeech
description: Text-to-speech React hook backed by the Microsoft Edge read-aloud service.
category: TTS
---
```

- `title` must match the export name. `description` is one or two plain sentences; it feeds search, `llms.txt` and `skills.md`.
- `category` reuses an existing value: `TTS`, `STT` or `UI`. Core class pages use `category: API Reference`.
- Start body headings at `##`.

Demos:

- Put demos in `src/react/<Name>/demos/`: `index.tsx` for the basic one, plus one file per idea (for example `AutoStop.tsx`). Each file has exactly one `export default` component.
- Import with `?demo` and render with `<Demo>`: `import DemoIndex from './demos/index.tsx?demo';` then `<Demo of={DemoIndex} layout="bare" />`.
- In demos, import the library by package name (`@lobehub/tts`, `@lobehub/tts/react`) so the source shown is copy-pasteable. Build UI with `@lobehub/ui`; playgrounds use `StoryBook`, `useControls` and `useCreateStore` from `@lobehub/ui/storybook`.
- Demos that need a key expose it as a control (see `src/react/useOpenAITTS/demos/index.tsx`) or call the local backends in `src/react/_util/api.ts`. Never hard-code secrets.

Preview and check:

- `bun run docs:dev` runs `lobedocs dev` together with `vercel dev`, which serves `api/` for the demos. Restart it after editing `docs.config.ts`.
- `bun run docs:build` builds the package and then runs `lobedocs build`, which validates every page.

## Adding a New Engine / Hook / Component

Follow the existing folders and copy their shape.

### Engine (`src/core/<Name>/`)

1. Create `src/core/<Name>/index.ts` with a class. Engines expose:

   - a constructor taking an `<Name>API` object (`serviceUrl`, `headers`, credentials as needed)
   - `create(payload): Promise<Response>`
   - `createAudio(payload): Promise<AudioBuffer>` for TTS (browser only), or `createText` for STT
   - `voiceOptions` and static `voiceList` / `localeOptions` where relevant

   Put request logic in its own file (for example `createEdgeSpeech.ts`) so it can be reused by `api/`.

2. Export the class and its `API` / `Payload` types from `src/core/index.ts`. `src/index.ts` re-exports it.

3. If the docs demos need a backend, add `api/<kebab-name>.ts` (Edge runtime, wrapped with `lib/cors.ts`) and its URL in `src/react/_util/api.ts`.

4. If it wraps an SDK for server use, add a helper in `src/server/` and export it from `src/server/index.ts`.

5. Document it in `docs/api-reference/` (see Writing Docs). Optionally add a script to `examples/text-to-speech-on-server/`.

### Hook (`src/react/use<Name>/`)

1. Create `src/react/use<Name>/index.ts`. TTS hooks build on the internal `useTTS` (`src/react/useTTS`), which handles segmenting and streaming; see `useEdgeSpeech`. STT hooks follow `useOpenAISTT` / `useSpeechRecognition`.
2. Export the hook and its `<Name>Options` type from `src/react/index.ts`.
3. Add `index.mdx` and `demos/index.tsx` in the same folder.
4. Low-level audio hooks without a docs page live in `src/react/hooks/`.

### Component (`src/react/<Name>/`)

1. Create `src/react/<Name>/index.tsx` with a `memo` component and an exported `<Name>Props` interface.
2. Document props with JSDoc; docs-kit reads them for `<Api>` tables.
3. Import components and styling helpers (`cssVar`, `createStaticStyles`, `cx`) from the `@lobehub/ui` root, and icons from `lucide-react`. In `@lobehub/ui` v6 the root export is the component set that used to live under `@lobehub/ui/base-ui`; that subpath no longer exists. Other entries are their own subpaths, such as `@lobehub/ui/storybook`, `@lobehub/ui/awesome` and `@lobehub/ui/icons`. v6 dropped `antd` and `antd-style`, and this package depends on neither; do not add them (ESLint does not block them, so check imports yourself).
4. Export the component and its props type from `src/react/index.ts`, then add `index.mdx` and `demos/`.

### Tests and final checks

Tests use Vitest (`vitest.config.ts`: jsdom, globals, `@/` alias). The repo currently has no test files. Add `*.test.ts(x)` next to the code or in `tests/` when logic is testable without network access.

Before committing, run:

```bash
bun run type-check
bun run lint
bun run lint:circular
bun run test --run
bun run build
```

Run `bun run docs:build` if you touched docs or demos.

## Conventions & Checks

| Command                 | What it does                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| `bun install`           | Install dependencies (lockfiles are gitignored; `.npmrc` / `.bunfig.toml` turn lockfile saving off) |
| `bun run dev`           | `tsdown --watch` (rebuild the package into `es/`)                                                   |
| `bun run build`         | Build the package with `tsdown`                                                                     |
| `bun run docs:dev`      | Docs site plus `api/` functions locally                                                             |
| `bun run docs:build`    | Build package and docs site                                                                         |
| `bun run type-check`    | `tsc --noEmit`                                                                                      |
| `bun run lint`          | ESLint on `src`, `api`, `lib` **with `--fix`**                                                      |
| `bun run lint:style`    | Stylelint with `--fix`                                                                              |
| `bun run lint:md`       | remark on all markdown (`--frail`; the README template has known long-line warnings)                |
| `bun run lint:circular` | dpdm circular-dependency check (also runs in pre-commit)                                            |
| `bun run test`          | Vitest (add `--run` for a single run)                                                               |

- Commits: gitmoji + conventional commit, lowercase scope if any, e.g. `✨ feat: add xxx hook`, `🐛 fix(react): ...`, `📝 docs: ...`. commitlint enforces this.
- Husky pre-commit runs `lint:circular` and lint-staged (prettier, remark, eslint, stylelint on staged files). Never bypass hooks with `--no-verify`; fix the cause.
- Releases are automated by semantic-release from commit messages. Do not bump `version` or edit `CHANGELOG.md`.
- Keep `README.md` focused on introduction and usage. API details belong in the docs site.
